# Automatic refresh and bounded recovery

- No Codex heartbeat or local computer is required. Existing GitHub Actions and the deployed Worker perform checks. GitHub schedules can be delayed; this is not a tick-level SLA.
- Comparison Monitor runs every 15 minutes. Existing domestic spot/FX/identity checks remain intact. Binance and Bybit futures now test the same public WebSocket paths used by the browser, requiring current prices for BTC, ETH and SOL. Coinbase tests the current authenticated bulk gateway cache. These source checks are not an exhaustive price reconciliation of every futures contract.
- The authenticated resources probe warms the shared L1/L2 fee and news caches and checks their actual successful refresh times. It also checks the market snapshot, DeFi and APYWA component health. Publication dates of news articles or 24-hour fee aggregation windows are not incorrectly treated as transport failure.
- Ordinary snapshot rebuilding, bounded retries, existing verified fallback paths and the refresh watchdog remain responsible for rebuilding and republishing market/DeFi/rating data. Browser stream watchdogs now detect stalled Binance and Bybit futures as well as Coinbase. Late/future/out-of-order source ticks are rejected for all three.
- News refreshes are coalesced; failures retain the last successful data and enforce a shared 60-second cooldown. Failed attempts never advance the original data timestamp.
- Detailed monitoring results and recovery transitions are stored in the existing private refresh history, which requires the administrator password again. A persistent failure alerts only after at least three checks spanning 30 minutes and is deduplicated until recovery. Public CI output contains aggregate counts, not private records.
- The release guard uses a same-origin HEAD request roughly every 10 minutes, with a second observation a minute later before a release reload. No full HTML download is used to check versions. It preserves the current route and reloads a given release at most once per tab. It skips hidden/offline tabs, login, board/news views, focused inputs and open dialogs. A deferred reload is retried after the protected interaction ends. Existing already-open code needs one reload to install this guard.
- No automatic arbitrary code edits, unverified API migrations, fabricated prices, login bypass, or paid feed is introduced. A permanently retired endpoint, upstream permission change or unavailable provider can still require a reviewed code change. Daily audit PDFs remain dated reports, not invented live holdings.
- The refresh watchdog pins GitHub's documented API version. After a transient dispatch error it checks whether the requested run already exists; ambiguous outcomes are left for the next scheduled check, never blindly redispatched or labeled as successfully repaired.

Tests: `node --test test_app_update.cjs test_futures_health.mjs test_comparison_health.cjs comparison-identity.test.cjs server-auth/board-permissions.test.mjs server-auth/security-regression.test.mjs`; existing browser regressions remain required.
