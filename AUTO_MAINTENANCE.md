# Automatic refresh and bounded recovery

- No Codex heartbeat or local computer is required. Existing GitHub Actions and the deployed Worker perform checks. GitHub schedules can be delayed; this is not a tick-level SLA.
- Comparison Monitor runs every 15 minutes. Existing domestic spot/FX/identity checks remain intact. Binance and Bybit futures now test the same public WebSocket paths used by the browser, requiring current prices for BTC, ETH and SOL. Coinbase tests the current authenticated bulk gateway cache. These source checks are not an exhaustive price reconciliation of every futures contract.
- The authenticated resources probe warms the shared L1/L2 fee and news caches and checks their actual successful refresh times. It also checks the market snapshot, DeFi and APYWA component health. Publication dates of news articles or 24-hour fee aggregation windows are not incorrectly treated as transport failure.
- Ordinary snapshot rebuilding, bounded retries, existing verified fallback paths and the refresh watchdog remain responsible for rebuilding and republishing market/DeFi/rating data. Browser stream watchdogs now detect stalled Binance and Bybit futures as well as Coinbase. Late/future/out-of-order source ticks are rejected for all three.
- News refreshes are coalesced; failures retain the last successful data and enforce a shared 60-second cooldown. Failed attempts never advance the original data timestamp.
- Detailed monitoring results and recovery transitions are stored in the existing private refresh history, which requires the administrator password again. A persistent failure alerts only after at least three checks spanning 30 minutes and is deduplicated until recovery. Public CI output contains aggregate counts, not private records.
- The release guard uses a same-origin HEAD request roughly every 10 minutes, with a second observation a minute later before a release reload. No full HTML download is used to check versions. It preserves the current route and reloads a given release at most once per tab. It skips hidden/offline tabs, login, board/news views, focused inputs and open dialogs. A deferred reload is retried after the protected interaction ends. Existing already-open code needs one reload to install this guard.
- No automatic arbitrary code edits, unverified API migrations, fabricated prices, login bypass, or paid feed is introduced. A permanently retired endpoint, upstream permission change or unavailable provider can still require a reviewed code change. Daily audit PDFs remain dated reports, not invented live holdings.
- The refresh watchdog pins GitHub's documented API version. After a transient dispatch error it checks whether the requested run already exists; ambiguous outcomes are left for the next scheduled check, never blindly redispatched or labeled as successfully repaired.

Tests: `node --test test_app_update.cjs test_futures_health.mjs test_comparison_health.cjs comparison-identity.test.cjs server-auth/board-permissions.test.mjs server-auth/security-regression.test.mjs`; existing browser regressions remain required.

## 2026-11-23 Maintenance Audit

- Initial baseline: 123 Node checks, 150 Python checks and all 12 browser suites passed. Production monitoring nevertheless reported 26 persistent alerts, demonstrating that mocked UI success is not evidence of healthy live providers.
- APYWA replaced its legacy `data-slug` rating table with the public `v2-asset`/`v2-grade` layout. The collector now supports both layouts and was verified against all 794 current public entries. Incomplete pages, invalid grades, unsafe links and unrelated same-ticker assets remain rejected. The new list does not publish individual evaluation dates; these remain explicitly unavailable, not copied from old ratings or invented from collection time.
- Market snapshot metadata and chunks now publish and read inside storage transactions. Injected mid-write failures roll back, concurrent readers cannot combine two generations, and older retry payloads receive HTTP 409 instead of replacing newer data. Same-generation retries remain supported.
- Queued and approval-waiting refreshes remain busy even after the normal execution timeout, preventing a backlog of duplicate recovery runs. A failed Comparison Monitor on the same repository's main branch now wakes the existing watchdog immediately; bounded cooldowns, manual-disable protection and authenticated publication remain intact.
- Comparison health rejects future, missing and non-finite catalog timestamps rather than treating those identities as healthy.
- Manual, push-triggered and recovery rebuilds now trigger a live comparison audit after completion. Normal scheduled rebuilds do not add a duplicate audit on top of the existing 15-minute monitor. Monitor configuration/policy changes also self-test immediately on main-branch pushes.
- Confirmed incidents remain latched through gaps in monitoring until an actual healthy observation. An unconfirmed streak still resets after a gap, so missed observations cannot fabricate a new persistent failure. Zero newly active alerts does not mean every comparison is healthy; inspect the delayed/identity counts too.
- Switching views now closes retired price subscriptions synchronously before deferred rendering/stream setup. A deterministic same-task browser regression covers the previously intermittent audit-navigation cleanup failure.
- A limited reviewed OKX fallback is explicitly partial and retries after five minutes, not six hours. Still-valid prior identities remain available with their original verification timestamp; they are neither erased by a one-asset fallback nor renewed as if the aggregator had succeeded. Existing 24-hour expiry and current native-quote requirements remain unchanged.
- Existing market, board, uploads, links, Korean search, charts, futures, issue caches and login regressions remain required. Tests do not modify real posts, memberships or uploads. Real-device Safari/iOS and an exhaustive penetration/load test remain outside this audit.
- GitHub scheduled jobs can still be delayed by the hosting platform. Persistent provider restrictions are kept visible in the private administrator history; successful workflow completion alone must not be presented as proof that every source recovered.

## 2026-11-23 Startup Follow-Up

- Reproduced a cold/reloaded market waiting behind an unrelated screen-settings request (up to its eight-second timeout). Settings and the snapshot now load concurrently; live-price refresh also does not wait for settings.
- Full local snapshots can exceed browser storage quotas. Failed full writes now fall back to a bounded market-only cache, with original snapshot timestamps and a complete server revalidation on every reload. Snapshot rendering precedes the deferred cache write, which checks the current login and snapshot before persisting.
- Pending or failed initial snapshots no longer claim that there are zero coins. Genuine successful empty results and search misses retain their existing empty state; no rows or fresh observation clocks are fabricated.
- The news/issue article delete action now sits at the bottom right with transparent, muted styling. Fresh-password checks, administrator-only visibility and automatic-news suppression remain unchanged.
- `test_market_startup.cjs` holds settings and snapshot responses independently, injects storage quota errors, checks cold/cache/retry/empty states and responsive layouts. It runs in the existing browser CI with no extra scheduled job. Existing issue tests cover the footer position and transparent background for both manual and automatic articles.

## 2026-11-23 Coin Detail Regression

- The compact startup cache introduced above omitted the entire coin-information map. This could show a false missing introduction and a symbol-only issue identity before the full response arrived. Compact entries now retain canonical names and logos, and modal lookup also uses the actual selected listing row. Existing empty-info startup caches are covered by regression tests.
- Complete introductions are retained separately in asynchronous IndexedDB instead of being discarded when localStorage is full. They restore only after server session confirmation, are owner/expiry guarded and identity checked, and do not replace a newer complete server response. Pending introductions no longer pretend to be missing. An open modal updates when cached or server introductions arrive without resetting its tab or draft.
- Only the hovered/focused or opened coin prefetches its first issue page. Shared pending requests coalesce with tab clicks; at most two speculative requests run, with bounded failure cooldowns. Fresh issue pages and their bounded inline bodies survive reload for the original 60-second validation window; cache reads never renew that window.
- Issue edits/deletions invalidate memory and persisted pages. Logout clears both stores and retires late reads/writes, with owner separation, expired/future cache rejection and a 32-entry persistent bound. Administrator password verification and server authorization are unchanged. A first uncached source still requires a real network response; no artificial zero-delay or live-price guarantee is made.
- Startup regressions now hold the full snapshot while opening BTC introduction/issues, exercise a legacy empty-info cache, verify the canonical `BTC:bitcoin` key, local quota recovery, same-click cached lists, no extra issue HTTP on reload, open-modal hydration, and account/logout races. Existing issue CRUD, suppression, revisions and draft tests remain required.
