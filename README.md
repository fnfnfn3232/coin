# 거래소별 시총 순위 보드

[index.html](C:\Users\wlvht\Documents\Codex\2026-04-22-spot-usdt\index.html) 를 브라우저에서 열면 됩니다.

`file://` 로 열면 거래소 API가 차단될 수 있습니다. 그 경우 `server.ps1` 로 로컬 서버를 띄운 뒤 `http://127.0.0.1:8791` 로 여는 방식이 더 안정적입니다.

포함된 기능:

- 바이낸스 `USDT` 현물 시총 순위
- 업비트 `KRW` 마켓 시총 순위
- 빗썸 `KRW` 마켓 시총 순위
- 100개 단위 페이지 이동
- 동시상장 종목 필터
  - 바이낸스 + 업비트 + 빗썸
  - 바이낸스 + 업비트
  - 바이낸스 + 빗썸

데이터 방식:

- 거래 가능 종목 목록은 각 거래소 공개 API 기준입니다.
- 시총은 CoinGecko 유통량과 각 거래소 현재가를 곱해서 계산합니다.
- 동시상장 여부는 심볼 기준으로 판별합니다.

체인 수수료:

- 자료의 `L1 수수료`, `L2 수수료`는 DefiLlama의 체인 자체 수수료(USD)를 24시간, 7일, 30일 기준으로 표시합니다. 체인 내 앱의 수수료 합계가 아닙니다.
- 검토한 체인 분류 목록 전체를 표시하며 25위 제한은 없습니다. L3, 사이드체인 및 분류가 불확실한 체인은 L1로 추정하지 않습니다. 데이터가 없는 값은 `-`입니다.
- 로그인한 회원만 조회할 수 있습니다. 두 화면은 서버의 10분 캐시와 진행 중 요청을 공유하며 실패하면 마지막 정상 데이터를 유지하고 1분 뒤 재시도합니다.
- 원본: https://defillama.com/fees/chains / 정의: https://docs.llama.fi/analysts/data-definitions

주의:

- 같은 심볼을 여러 프로젝트가 공유하는 경우 CoinGecko 매칭 오차가 생길 수 있습니다.
- `file://` 환경에서 브라우저 보안 정책이나 거래소 CORS 정책 때문에 일부 API 호출이 막힐 수 있습니다.

자동 갱신 복구:

- 공지 수집은 실패한 출처를 잠시 쉬게 하고 다음 정상 출처로 전환합니다. 403은 30분부터 최대 6시간, 일시 오류는 5분부터 최대 1시간 대기 후 재확인합니다. 업비트는 두 공식 API와 공식 공개 공지 채널을 사용합니다.
- 보호된 데이터의 `noticeRefresh.providers`와 `refreshHealth.components`에 경로별 재시도 시각, 항목별 마지막 정상 확인 시각 및 연속 실패 횟수를 보관합니다. 이전 데이터 재사용을 새 정보 수집 성공으로 기록하지 않습니다.
- `Auto Refresh Data`는 기존 갱신 주기를 유지합니다. 3회 연속 실패하거나 30분 이상 지연된 항목은 자동 장애 이슈에 기록합니다. 전체 빌드·게시 실패도 기록합니다. 정상 복구 후 이슈를 자동 종료하며 같은 장애를 매번 새로 만들지 않습니다.
- 별도 `Refresh Watchdog`가 15분 간격으로 갱신 작업을 점검합니다. 30분 이상 성공이 없고 최근 작업이 진행 중이지 않으면 복구 실행을 요청합니다. 수동 중지는 존중하고 GitHub의 비활동 자동 중지만 해제합니다.
- 장애 이슈에는 항목 이름과 실행 기록 링크만 기록합니다. 회원 정보, 첨부파일, 보호된 시세 원본, 인증 정보는 공개하지 않습니다. 이메일 알림 수신 여부는 GitHub 저장소 알림 설정에 따릅니다.
- PC나 Codex 실행 여부와 무관하게 GitHub에서 동작하며 AI API는 사용하지 않습니다. GitHub 전체 장애, 모든 공식 출처의 장기 차단, API 규격 변경을 임의로 코드 수정해서 해결하지는 않습니다. 이때는 마지막 정상 자료와 지연 표시를 유지하고 사람의 확인이 필요합니다. GitHub 예약 실행 자체가 중단되면 이 감시 작업도 실행되지 않을 수 있습니다.

갱신 기록:

- 시총 화면의 거래소 현황 아래 `갱신 기록`에서 현재 지연 항목, 장애 감지, 예비 경로 사용·전환, 반복 장애, 정상 복구를 확인할 수 있습니다. 날짜와 시간은 한국시간으로 표시합니다.
- 자동 기록은 보호된 서버 데이터에 저장하고 다음 갱신에 이어받습니다. 상태가 바뀔 때만 추가하며 최근 90일, 최대 200건을 유지합니다. 정상 수집이 확인되기 전에는 복구 완료로 기록하지 않습니다. 기록 기능 도입 전의 성공이나 복구를 추정해 만들어내지 않습니다.
- 개발자가 코드를 수정한 내역은 `.github/maintenance_history.json`에 확인된 커밋 SHA, 커밋 시각과 수정 내용을 등록합니다. 자동 처리와 별도로 표시하고 실제 코드 변경으로 연결합니다. 확인되지 않은 미래 배포를 완료로 등록하지 않습니다. 이 파일은 Pages 배포 대상이 아닌 경로에 둡니다.
- 기록을 열 때마다 `POST /api/admin/refresh-history`가 활성 로그인과 새로 입력한 관리자 비밀번호를 모두 확인합니다. 관리자 역할이나 이메일 로그인만으로 이 검사를 생략하지 않습니다. 일반 시세 응답에는 상세 기록·진단 정보를 포함하지 않고, GitHub OIDC로 검증된 내부 갱신 작업만 전체 자료를 이어받습니다.
- 비밀번호와 조회 결과는 브라우저 저장소에 저장하지 않습니다. 창을 닫거나 로그아웃·인증 만료 시 조회 자료를 지우며 늦게 도착한 응답도 무시합니다. 비밀번호 인증 후 기록 구분은 받은 자료만 사용합니다. 기록 파일을 읽지 못해도 시세 갱신 자체는 중단하지 않고 이전 기록을 유지합니다.
- 공개 GitHub 저장소의 기존 커밋·소스 기록은 사이트의 비밀번호 보호와 별개이며, 이미 공개된 자료를 이 인증 기능으로 소급 비공개로 만들 수는 없습니다.
